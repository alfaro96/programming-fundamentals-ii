# Naming and defining identifiers

This example **demonstrates** the **rules** for **defining valid identifiers** and highlights common naming errors that prevent the code from compiling.

---

## What does it do?

The program `Naming` **defines** several **variables** to show the **difference** between **valid** and **invalid identifiers**:

* The program **declares variables** using letters, digits, and special characters like underscores or dollar signs to **validate syntax rules**.
* It **illustrates** that **identifiers cannot start** with **numbers** and must **avoid** using **reserved keywords**.
* The code **demonstrates** the **use** of `camelCase` as the **standard convention** to make **variable names** more **readable**.
* Several **commented-out lines** show exactly which **naming patterns** will trigger a **compiler error**.
* It **highlights** that **Java** is **case-sensitive**, meaning two variables with the same letters but different casing are treated as unique.

---

## Key concepts

* **Valid identifiers** must **start with** a **letter**, a dollar sign `$`, or an underscore `_`.
* **Numbers** can be **included** in a variable name, **but** they **cannot** be the **first character**.
* **Reserved keywords** are **strictly forbidden** because they have a predefined meaning in the language.
* `camelCase` **convention** is the **standard practice** where the first letter is lowercase and subsequent words start with a capital letter.
* **Meaningful names** help **improve code maintainability** by clearly describing what data the variable holds.
