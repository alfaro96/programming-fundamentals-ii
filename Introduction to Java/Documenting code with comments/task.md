# Documenting code with comments

This example **demonstrates** how to **use** different types of **comments** to explain logic and **improve readability** without affecting the program's execution.

---

## What does it do?

The program `Comments` includes **various ways** to **document code**:

* **Single-line comments** are **used** with `//` to explain **specific lines** of code.
* **Multi-line comments** are **implemented** with `/* ... */` to describe **larger blocks** or logic flows.
* **Javadoc comments** are **added** using `/** ... */` to create **professional documentation**.
* It **shows** that the **compiler completely ignores everything** inside comments, meaning they have zero impact on the final performance of the application.
---

## Key concepts

* **Single-line comments** using `//` are the best choice for **short notes** or for **disabling a single line** of code during testing.
* **Multi-line comments** enclosed in `/* */` are ideal for **long explanations**, headers, or documentation **that spans several lines**.
* **Javadoc comments** starting with `/**` are **special markers** that can be processed by tools to **generate documentation** automatically.
* **Code maintenance** is significantly **improved when good comments help** developers **understand** the **purpose behind** the **code** rather than just the syntax.
